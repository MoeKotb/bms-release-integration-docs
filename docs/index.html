Mastermind BMS Release integration guide

Connect Vercel access to the BoostMySEO release workflow using an installation limited to the BoostMySEO project.

This is a private operational integration. Installation does not initiate a deployment. Release approval and deployment checks remain separate requirements.

1. Prerequisites

  • Authorization from the BoostMySEO operator to manage its releases.
  • Access to the Vercel team that owns the BoostMySEO project, with permission to install integrations.
  • An operator-provided installation link for the private integration and a configured authorization callback.
  • Review of the integration EULA, product terms, and privacy policy.

2. Requested Vercel permissions

Permissions for the project-limited installation
PermissionAccessPurpose
Integration ConfigurationReadVerify the installation, its selected project, and approved permissions.
ProjectsReadConfirm the identity and repository connection of BoostMySEO.
DeploymentsRead/WriteInspect and manage deployments for the authorized project. This permission can affect production deployments.

The setup does not request environment-variable, domain, billing, team-directory, or current-user API permissions. Select only BoostMySEO when granting project access. Do not grant access to all projects.

3. Installation

  1. Open the private installation link supplied by the authorized operator.
  2. Choose the Vercel team that owns BoostMySEO.
  3. Select access to specific projects and choose only boostmyseo.
  4. Review the three permissions above and complete the installation approval in Vercel.
  5. Allow Vercel to return to the configured callback. The operator's exchange process verifies the team, project, and permission set before accepting the installation token.
  6. Confirm that the operator reports project-scope verification as successful before using the integration.

If the callback or scope verification fails, stop setup and contact the operator. Do not broaden access to work around a failure. Authorization codes and tokens must be handled through the approved private setup process.

4. Release operation

  1. Confirm the project, repository, candidate revision, and intended deployment environment.
  2. Review the required checks and obtain release approval before initiating a production deployment.
  3. Use the installation token only through the authorized release tooling.
  4. Review deployment status and preserve a credential-free record of the result.

A successful connection or deployment does not establish that application tests, database migrations, or release approval have passed. Failed checks must be resolved before proceeding.

5. Data and credentials

The workflow accesses the integration configuration, selected-project metadata, and deployment information allowed by Vercel. Deployment information may include operational details returned by Vercel. Authorization credentials are handled on operator-controlled infrastructure and used for authorized API requests. Never place credentials in this documentation, public repositories, screenshots, or support messages.

These static documentation pages do not contain an authorization callback, credential form, or analytics script. GitHub hosts the pages and may process visitor request information under GitHub's privacy statement. BoostMySEO's processing is described in its Privacy Policy. Contact support for access, deletion, or security requests.

6. Disconnect or revoke access

In Vercel, open the owning team's Integrations settings, locate this installation, and remove it or revoke its project access. Ask the authorized operator to remove stored installation credentials. Verify that subsequent API requests are denied. Disconnecting prevents future authorized API use; it does not undo deployments already performed. Vercel controls token validity and revocation.

7. Troubleshooting

  • Integration not visible: confirm the correct team and use the private link supplied by the operator.
  • Wrong project or extra permissions: cancel authorization and restart with only BoostMySEO and the documented permissions.
  • Callback unavailable: ask the operator to restore the configured callback before retrying.
  • Access denied after setup: check that the installation remains active and includes the selected project. Do not substitute a broad personal token.
  • A release check fails: keep the release pending and provide the error category, time, and project name to the operator.

8. Support

Email support@boostmyseo.app with the project name, time, and a redacted error description. Never include a token, client secret, password, or authorization code.
